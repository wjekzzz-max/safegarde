# SAFE 실제 사용 및 배포 가이드

장치가 보내야 할 URL, 헤더와 JSON 바디의 정확한 규격은 [docs/DEVICE-API.md](docs/DEVICE-API.md)를 참고하세요.

이 문서는 SAFE 프로젝트를 더미 데이터가 아닌 **Arduino Nano ESP32 + MAX30102 + 6축 IMU 실제 장치**로 운영하기 위한 절차를 설명합니다.

> 현재 저장소는 시제품 단계입니다. 의료 진단 장비 또는 법적 안전장치로 인증된 시스템이 아닙니다. 현장 적용 전 산업안전 담당자 검토, 충분한 데이터 수집, 오탐·미탐 시험과 개인정보 보호 대책이 필요합니다.

## 1. 실제 운영 구조

Nano ESP32와 관리자 PC는 같은 Wi-Fi에 있을 필요가 없습니다. 두 장치가 각각 인터넷에 연결되고, 가운데 백엔드가 공용 HTTPS 주소로 배포되어 있으면 됩니다.

```text
[작업자 장치]
Nano ESP32 + MAX30102 + 6축 IMU
        │
        │ 현장 Wi-Fi 또는 LTE/5G 라우터
        │ HTTPS POST /api/telemetry
        ▼
[공용 백엔드]
https://api.example.com
        │
        ├─ 상태 판정
        ├─ 관리자 알림 생성
        └─ 데이터 저장
        │
        ▼
[관리자]
웹 브라우저 또는 관리자 태블릿
```

다음 주소는 외부 네트워크에서 사용할 수 없습니다.

```text
http://localhost:4000
http://127.0.0.1:4000
http://192.168.x.x:4000
http://10.x.x.x:4000
```

실제 장치에는 인터넷에서 접근 가능한 주소를 사용해야 합니다.

```text
https://api.example.com/api/telemetry
```

## 2. 필요한 장비

- Arduino Nano ESP32
- MAX30102 심박수·산소포화도 센서 모듈
- MPU6050 등 3축 가속도 + 3축 자이로를 제공하는 6축 IMU
- 안정적인 3.3V 전원 및 배터리
- 작업자 착용용 케이스와 센서 고정 구조
- 현장 Wi-Fi 또는 인터넷 연결이 가능한 LTE/5G 라우터
- 공용 HTTPS 백엔드를 실행할 서버
- 관리자용 PC, 태블릿 또는 스마트폰

센서 모듈의 허용 전압은 제품마다 다를 수 있습니다. Nano ESP32 핀에 연결하기 전에 사용하는 모듈의 데이터시트와 보드 회로를 확인하세요.

## 3. 개발 단계와 실제 운영 단계의 차이

| 항목 | 현재 데모 | 실제 운영에 필요한 구성 |
| --- | --- | --- |
| 데이터 | 메모리 더미 데이터 | 실제 센서 측정값 |
| 백엔드 주소 | localhost | 공용 HTTPS 도메인 |
| 저장소 | 서버 메모리 | PostgreSQL 등 영구 DB |
| 장치 인증 | 선택적 API 키 | 장치별 키 또는 인증서 |
| 관리자 인증 | 없음 | 로그인 및 권한 관리 |
| 알림 | 웹 내부 알림 | 푸시, 문자, 이메일 등 |
| HTTPS 검증 | 개발용 우회 가능 | CA 인증서 검증 필수 |
| 장애 처리 | 없음 | 재전송, 로컬 버퍼, 모니터링 |

## 4. 백엔드 배포

### 4.1 배포 조건

백엔드 실행 환경은 다음 조건을 만족해야 합니다.

- Node.js 실행 지원
- 외부 HTTPS 요청 수신 가능
- 환경 변수 설정 가능
- 지속적으로 실행되는 프로세스
- 고정된 공용 도메인
- 운영 단계에서는 영구 데이터베이스 사용

### 4.2 환경 변수

`.env.example`을 복사해 로컬 시험용 `.env`를 만들거나, 배포 서비스의 환경 변수 화면에 직접 등록합니다.

```env
HOST=0.0.0.0
PORT=4000
DEVICE_API_KEY=충분히-길고-무작위인-비밀값
```

실제 `.env`와 장치 키는 Git 저장소에 올리지 마세요.

현재 서버는 `DEVICE_API_KEY`가 설정된 경우 다음 헤더를 검사합니다.

```http
X-Device-Key: 장치-비밀키
```

운영 환경에서는 하나의 공용 키보다 장치별 키를 발급하고, 키를 해시하여 데이터베이스에 저장하는 방식을 권장합니다.

### 4.3 실행 확인

배포 후 브라우저나 API 도구로 상태 확인 API를 호출합니다.

```http
GET https://api.example.com/api/health
```

정상 응답:

```json
{
  "ok": true,
  "service": "safe-api"
}
```

`http://`가 아닌 `https://`로 접근되는지 반드시 확인합니다.

## 5. 프런트엔드 배포

프런트엔드를 빌드합니다.

```bash
npm install
npm run build
```

결과물은 `dist/`에 생성됩니다. 정적 웹 호스팅 또는 백엔드 리버스 프록시를 통해 배포합니다.

현재 프런트엔드는 `/api` 상대 경로를 사용합니다. 가장 단순한 운영 구조는 같은 도메인에서 다음처럼 경로를 나누는 것입니다.

```text
https://safe.example.com/       → React 프런트엔드
https://safe.example.com/api/*  → Express 백엔드
```

프런트엔드와 백엔드 도메인을 분리하려면 `src/api.js`가 환경 변수의 API 주소를 사용하도록 추가 설정해야 합니다.

## 6. Nano ESP32 펌웨어 준비

기본 예제는 다음 파일입니다.

```text
firmware/nano-esp32-max30102-imu.ino
```

다음 값을 실제 환경에 맞게 수정합니다.

```cpp
const char* WIFI_SSID = "현장 Wi-Fi 이름";
const char* WIFI_PASSWORD = "현장 Wi-Fi 비밀번호";
const char* API_URL = "https://safe.example.com/api/telemetry";
const char* DEVICE_API_KEY = "서버에 등록한 장치 키";
```

Arduino IDE에서 보드를 `Arduino Nano ESP32`로 선택하고 업로드합니다. 시리얼 모니터 속도는 `115200 baud`입니다.

현재 펌웨어의 센서값은 더미값이므로 다음 부분을 실제 라이브러리 측정 결과로 교체해야 합니다.

```cpp
int heartRate = 78;
int spo2 = 98;
long ir = 86420;
long red = 68110;
float ax = 0.02, ay = -0.03, az = 1.00;
float gx = 1.2, gy = -0.8, gz = 0.4;
```

## 7. 실제 센서 데이터 처리

### 7.1 MAX30102

MAX30102의 IR/Red 원시 샘플을 읽은 뒤 필터와 계산 알고리즘으로 심박수 및 SpO₂를 추정합니다.

실제 구현 시 확인할 항목:

- 피부 접촉 여부
- 주변광 유입
- 손목 움직임에 의한 노이즈
- LED 밝기와 샘플링 설정
- 유효하지 않은 BPM·SpO₂ 값 제거
- 측정 안정화 전 데이터 전송 방지

MAX30102는 의료용 확정값을 직접 제공하지 않습니다. 착용 방식과 알고리즘에 따라 결과가 크게 달라집니다.

### 7.2 6축 IMU

IMU에서 읽는 값:

```text
ax, ay, az = 중력가속도 단위 g
gx, gy, gz = 각속도 단위 °/s
```

여기서 `g`는 그램이 아닌 중력가속도입니다.

```text
1g ≈ 9.81m/s²
```

센서 원시값은 설정 범위에 맞는 변환 계수를 적용해야 합니다. 예를 들어 특정 IMU의 ±2g 또는 ±250°/s 설정은 각각 다른 변환 계수를 사용할 수 있으므로 사용 중인 센서 데이터시트를 기준으로 구현하세요.

## 8. 넘어짐 판정 구현

현재 서버 데모는 다음 조건을 사용합니다.

- 합성 중력가속도 2.5g 이상 충격
- 자세 기울기 60° 이상
- 충격 후 2초 이상 무동작

실제 운영에서는 한 번의 HTTP 요청만으로 넘어짐을 결정하지 말고 Nano ESP32에서 고속으로 IMU를 샘플링하며 상태를 추적해야 합니다.

```text
NORMAL
  │ 순간적인 저중력 또는 빠른 회전
  ▼
POSSIBLE_FALL
  │ 2.5g 이상 충격
  ▼
IMPACT
  │ 60° 이상 자세 변화
  ▼
LYING
  │ 2초 이상 낮은 움직임
  ▼
FALL_CONFIRMED
```

권장 방식:

1. IMU를 50~100Hz 이상으로 읽습니다.
2. 최근 수 초의 샘플을 순환 버퍼에 저장합니다.
3. 충격 시점을 기록합니다.
4. 충격 후 제한 시간 안에 자세가 크게 바뀌었는지 확인합니다.
5. 합성 중력가속도가 1g 부근에서 안정되고 각속도가 낮은 상태가 유지되는지 확인합니다.
6. 조건이 유지되면 넘어짐 이벤트를 서버로 전송합니다.
7. 작업자가 취소 버튼을 누르면 오탐으로 기록합니다.

걷기, 뛰기, 점프, 의자에 앉기, 공구 충격 등도 높은 가속도를 만들 수 있으므로 `2.5g` 하나만으로 넘어짐을 판정하면 안 됩니다.

## 9. 텔레메트리 전송

Nano ESP32는 다음 API를 호출합니다.

```http
POST https://safe.example.com/api/telemetry
Content-Type: application/json
X-Device-Key: 장치-비밀키
```

요청 예시:

```json
{
  "deviceName": "SAFE-NANO-001",
  "heartRate": 78,
  "spo2": 98,
  "ir": 86420,
  "red": 68110,
  "signalQuality": 95,
  "fingerDetected": true,
  "rssi": -55,
  "imu": {
    "accelerometer": { "x": 0.02, "y": -0.03, "z": 1.0 },
    "gyroscope": { "x": 1.2, "y": -0.8, "z": 0.4 },
    "stillnessMs": 0
  }
}
```

전송 주기는 현재 화면 기준 2.5초지만, 실제 구현에서는 다음 두 주기를 분리하는 것이 좋습니다.

```text
IMU 내부 샘플링: 50~100Hz 이상
서버 텔레메트리: 1~5초 간격 또는 이벤트 발생 즉시
```

## 10. 통신 장애 처리

Nano ESP32는 항상 인터넷에 연결되어 있다고 가정하면 안 됩니다.

필수 처리:

- Wi-Fi 끊김 자동 재접속
- HTTP 요청 제한 시간 설정
- 실패한 이벤트의 로컬 큐 저장
- 지수 백오프 재전송
- 중복 전송 구분용 이벤트 ID
- 서버 마지막 수신 시간 기반 오프라인 판정
- 일정 시간 전송 실패 시 장치 LED 또는 부저 표시

넘어짐 이벤트는 일반 상태 데이터보다 우선적으로 전송해야 합니다.

## 11. HTTPS 보안

예제 펌웨어의 다음 코드는 개발 편의를 위한 설정입니다.

```cpp
secureClient.setInsecure();
```

이 설정은 서버 인증서를 검증하지 않기 때문에 실제 운영에 사용하면 안 됩니다. 운영 펌웨어에서는 공용 서버 인증서를 발급한 CA의 인증서를 Nano ESP32에 등록하고 검증해야 합니다.

추가 보안 권장 사항:

- 장치별 API 키 발급 및 폐기 기능
- 관리자 로그인과 역할 기반 권한
- 텔레메트리 요청 크기 및 빈도 제한
- 모든 통신 HTTPS 적용
- 비밀키를 소스 코드 저장소에 커밋하지 않기
- 키 노출 시 원격 교체 절차 마련
- 서버와 데이터베이스 백업
- 작업자 개인정보 암호화 및 보존 기간 설정

## 12. 현장 시험 순서

실제 사람에게 착용하기 전에 다음 순서로 시험합니다.

### 단계 1: 서버 시험

- `/api/health`가 외부 네트워크에서 응답하는지 확인
- 올바른 API 키는 200, 틀린 키는 401인지 확인
- 미등록 장치는 404인지 확인
- 서버 재시작과 장애 시 복구 여부 확인

### 단계 2: 장치 통신 시험

- Nano ESP32를 관리자 PC와 다른 네트워크에 연결
- 시리얼 모니터에서 HTTP 200 확인
- 관리자 화면에서 RSSI와 마지막 수신 시간 확인
- Wi-Fi를 끊었을 때 15초 이후 오프라인 표시 확인
- Wi-Fi 복구 후 자동 재전송 확인

### 단계 3: 센서 시험

- 정지 상태의 합성 중력가속도가 약 1g인지 확인
- 각 축의 방향과 부호 확인
- 센서를 90° 회전했을 때 기울기 표시 확인
- 완충재와 시험 장비를 이용해 충격 임계값 확인
- MAX30102 접촉 해제 시 미접촉 상태 확인

### 단계 4: 넘어짐 알고리즘 시험

- 걷기, 달리기, 앉기, 점프를 넘어짐으로 오인하지 않는지 확인
- 앞, 뒤, 좌, 우 방향 넘어짐 데이터를 각각 수집
- 작업복과 착용 위치가 바뀌어도 판정되는지 확인
- 오탐률과 미탐률을 기록하고 임계값 조정

실제 사람에게 고의로 넘어지게 하는 시험은 피하고, 초기 시험에는 마네킹, 센서 모형, 충격 완충재를 사용하세요.

## 13. 운영 전 필수 개선 사항

현재 코드 그대로 장기 운영하기 전에 다음 항목을 구현해야 합니다.

- PostgreSQL 또는 다른 영구 데이터베이스
- 작업자·장치 등록 및 수정 API
- 장치별 인증키
- 관리자 로그인과 접근 권한
- 알림 전송 실패 재시도
- 문자, 앱 푸시, 이메일 등 실제 관리자 알림
- 센서 배터리 잔량 전송
- 장치 펌웨어 버전 관리
- 서버 로그와 장애 모니터링
- 개인정보 동의, 암호화, 보존 및 삭제 정책
- 오탐 취소와 사고 처리 이력
- 서버 시간과 장치 시간 동기화

## 14. 실제 운영 체크리스트

- [ ] 백엔드에 공용 HTTPS 도메인이 있다.
- [ ] 외부 네트워크에서 `/api/health`가 응답한다.
- [ ] `DEVICE_API_KEY`가 설정되어 있다.
- [ ] Nano ESP32 API 주소가 `https://`로 시작한다.
- [ ] 운영 펌웨어에서 TLS 인증서를 검증한다.
- [ ] 센서값이 더미값이 아닌 실제 측정값이다.
- [ ] IMU 영점과 축 방향을 보정했다.
- [ ] 착용 위치별 넘어짐 임계값을 검증했다.
- [ ] Wi-Fi 장애 시 재접속과 데이터 재전송이 동작한다.
- [ ] 데이터가 영구 데이터베이스에 저장된다.
- [ ] 관리자 인증과 권한이 적용됐다.
- [ ] 실제 알림 채널과 재전송이 동작한다.
- [ ] 오탐·미탐 시험 결과를 기록했다.
